# Project charter

## Problem statement
A fictional growing professional-services organization needs a sustainable Microsoft 365 operating model. Existing controls and maturity are unknown until assessed. Leadership seeks AI adoption alongside reliable daily operations.

## Stakeholders
Executive sponsor, IT platform owner, security/compliance representatives, departmental process owners, service desk and end users. Proposed roles, not actual appointments.

## Success criteria
- A documented inventory schema and discovery process covering sites, apps, flows and agents.
- Governance controls with named accountable roles, exception handling and verification methods.
- A prioritized risk register with owners and mitigation actions.
- A pilot plan specifying scope, access checks, success measures and stop criteria.
- A 90-day roadmap with dependencies and decision gates.
- A synthetic dataset and documented KPI calculations for reporting.

## Constraints
No production access or real client information. Licensing and feature availability must be verified before recommending implementation. No claims of deployed controls or realized savings.

## Decision rights
The platform owner proposes controls and manages implementation. Security and compliance review relevant risks. Business owners validate process requirements. The executive sponsor resolves funding and policy trade-offs. Actual authority must be agreed before implementation.

## Definition of done
Each deliverable identifies assumptions, rationale, accountable roles, verification criteria and unresolved risks. Changes are reviewed through Git before publication. Technical recommendations cite current authoritative documentation when developed.
